# R12 호출·지연 회귀 비교

이 자료는 R12 1차 실행 기록이다. 최신 제품의 최대 2회 방식과 후속 긴 대기 비교는 [R12 2차](../r12-tail-v2/README.md)에 있다.

2026년 11월 2일. 기준 커밋 `7dfd18d`. [사전 실행 계획](plan.json).

## 비교 방법

R10·R11의 cases/contexts와 사진 해시는 변경하지 않는다. 이미 개발에 사용한 28개이므로 이번에는 고정 **회귀 세트**이며 새로운 독립 평가가 아니다. 알려진 AI 연출 사진과 수동 규칙을 사용한다.

- `full`: 종전 계획 + 전체 답변 재검토, 매 질문 2회.
- `adaptive`: 최초 계획은 동일. 새 단순 외형 질문만 1회. 업무·조건·대상 선택·확인 대화·미해결·업무 표현이 들어간 질문/초안은 짧은 별도 검토를 유지한다. 잘못된 후보라면 종전 전체 교정 호출을 추가해 최대 3회다.
- 사례당 두 방식을 각각 실제 API로 새로 실행한다. 초안·응답 캐시를 공유하지 않는다. seed 1207로 사례 순서를 섞고, 방식 선후를 14개씩 교대한다. 동시 최대 2개, 자동 재시도 없음.
- 소요 시간은 서버 답변 함수 전체의 실제 대기 시간이다. 브라우저 통신·렌더링·SAM 시간은 포함하지 않는다. 실패도 결과에 남기며 품질 또는 지연이 나쁜 사례를 제외하지 않는다.
- 원래 채점 기준을 그대로 사용한다. 목적/상태 28개, 대상/판정과 필수 인용 17개, 금지·조건부의 잘못된 허용 12개를 구분한다. 전체 문맥 펼치기는 정답 근거로 계산하지 않는다.

## 재현

```sh
python3 scripts/benchmark_latency.py
python3 scripts/benchmark_latency.py --execute
```

첫 명령은 호출 없는 계획 확인이다. 두 번째는 기존 Meta 설정으로 실제 유료 요청을 실행한다. 28개 × (full 최대 2 + adaptive 최대 3) = 최대 140회이며, 실패 시 임의 재시도하지 않는다. 결과에는 설정값·키·사진 요청 본문을 포함하지 않는다. actual token 합계는 실패 응답에 사용량이 없는 경우 청구 집계가 될 수 없다.

## 실패 기록과 한계

초기 대형 중첩 교정 스키마는 V03 검토에서 시간 초과해 폐기했다. 원인으로 스키마 처리 비용과 공급자/통신 변동을 구분할 증거는 없다. 최종 방식은 작은 승인/교정 필요 판정만 생성하며, 교정은 필요한 경우에만 별도 호출한다. 이 실패도 canary 결과에 보존한다.

같은 모델의 재검토는 독립된 사람 검수가 아니다. 한 번의 교대 실행으로 공급자 변동을 제거할 수 없다. 단순 외형 검토를 생략하는 정책은 일반 의미 오류가 없다는 보장이 아니며, 고정 세트 결과를 새로운 사진·현장 정확도로 표현하지 않는다. 사용자 대기 수용성·외부 사람 평가·새 사진 검증은 남아 있다.

최종 수치와 브라우저 검증은 [R12 보고서](../../docs/R12_RESULTS.md)에 기록한다. results에는 최종 서비스 응답, 실행 소스 해시, 사례별 소요 시간과 요약을 보관한다.
