# R10·R11 사전 고정 평가 세트

2026년 11월 2일. 기준 `953d414`의 소스·검사·문서·기존 평가에서 그대로 사용한 질문과 겹치지 않는 28개 질문을 구현 전에 고정했다. cases.json·contexts.json의 SHA-256은 manifest.json에 기록했다. 현재 실행기는 해시가 다르면 중단한다.

## 분리와 독립성의 범위

| 구분 | 사례 | 역할 |
|---|---:|---|
| discovery | 12 | 수정 전 실패 발견과 수정용 |
| validation | 8 | 중간 단계에서 다른 작업·조건 확인 |
| sealed | 8 | 최종 추론 구현의 첫 평가. 결과를 보고 모델/프롬프트를 다시 수정하지 않음 |

sealed는 수정 선택에서 따로 둔 사례라는 뜻이며 접근 제어된 외부 블라인드 세트라는 뜻은 아니다. Codex가 같은 작업 안에서 질문·기준을 작성하고 검토했다. 원본 사진은 이미 알려진 AI 연출 이미지 1장을 재사용한다. 새 사진 일반화·외부 사람 평가·실제 현장 효과로 해석하지 않는다. 수정 전 역할과 다른 출입증/보관표/대여표/견학증 규칙을 수동으로 작성해 제공했다.

AND·OR, 정보 부족, 추가 조건, 대상 바꾸기와 선택 지점의 대상을 포함한다. 선택 지점이 있는 오프라인 사례의 영역은 작성한 평가 입력이며 실제 SAM 호출 결과라고 주장하지 않는다. 제품 브라우저 검증에서는 별도로 실제 SAM을 호출했다.

## 판정 기준

- 요청 정보의 목적, 응답 상태, 관련 승인 문구를 따로 확인한다.
- 적용 질문은 예상 대상과 policy/allowed/blocked/conditional 판정을 사전 라벨과 비교한다.
- 원문 전체를 approved_context에 붙이는 것만으로 정답 처리하지 않는다. 선택된 답변·인용에서 필수 규칙을 확인한다.
- 금지·조건부를 allowed로 판정한 경우를 별도로 센다.
- 구조화한 상태/문자열 검사는 의미 전반의 증명이 아니므로 내부 텍스트·사진 검토를 별도 기록한다.

기존 버전에는 assessment 자체가 없다. baseline-summary의 decision_match 0/7은 새 응답 계약을 충족하지 않는다는 뜻이며, 과거 모델의 의미 정확도가 0%였다는 뜻이 아니다. 기존 원문 인용은 관련성이 있었지만 조건 충족/미충족 질문에 같은 정책을 제시했다. 이 차이를 [전체 보고서](../../docs/R10_R11_RESULTS.md)에 구분했다.

quote_coverage는 필수 인용 항목이 없는 사례에서 자명하게 true다. 의미/조건 정확도를 그 수치 하나로 계산하지 않는다.

## 실행과 저장 자료

`python3 scripts/evaluate_semantics.py --split sealed`는 해시와 호출 계획만 확인한다. `--execute`를 붙이면 실제 API를 호출한다. baseline 모드는 이전 단일 호출·표현 규칙 경로를, current 모드는 현재 제품의 의미 판단 서비스를 사용한다. 최대 작업자 2개, 자동 재시도 없음. 기존 안내서·승인본·질문 DB는 변경하지 않는다.

아래 R10·R11 당시 실행은 자동/업무 질문에 초안과 일관성 검토로 모델을 두 번 호출했다. 명시적인 사진 전용 질문은 한 번이었다. 현재 제품의 R12 적응 검토와 같은 세트 재실행은 [R12 회귀 비교](../r12-latency-v1/README.md)를 참고한다. API 요청 수와 질문 사례 수를 구분한다.

results에는 단계별 manifest·원본 응답·요약과 내부 검토를 보관한다. discovery/validation은 개발 중 버전 실행이며, 최종 구현에 대한 별도 판정은 sealed 실행으로 한정한다. 최종 manifest는 추론/API 소스 해시를 포함한다. 모든 단계의 집계만으로 일반적인 정확도 100%를 주장하지 않는다.

| 실행 | 목적 일치 | 대상·판정 라벨 일치 | 오류 |
|---|---:|---:|---:|
| 수정 전 discovery | 8/12 | 구조화된 판정 없음 | 0 |
| 수정 후 discovery | 12/12 | 7/7 | 0 |
| validation | 8/8 | 5/5 | 0 |
| 최종 sealed | 8/8 | 5/5 | 0 |

최종 8개에서 금지/조건부 4개를 허용으로 판정한 경우는 없었다. 두 번 검토하는 방식의 비용도 확인했다. 현재 단계 실행 28개 기준 대기 중앙값은 23.051초, 최대는 57.890초였다. 속도와 외부 평가 과제는 별도로 남는다.

최종 실행 뒤에는 모델 입력을 바꾸지 않고 스키마의 일관성 제약을 런타임에도 강제했다. 저장된 평가 28개·실제 앱 4개 응답의 재생 검사로 확인했으며 새 모델 호출로 세지 않는다. 실행 시점 소스 해시와 이후 계약 검사를 구별한다.

현재 R12 2차의 긴 대기 비교는 [추론 깊이·전체 교정 회귀](../r12-tail-v2/README.md)에 별도로 기록한다. 기존 28개를 바꾸지 않은 재실행이며 새 블라인드 평가가 아니다.
