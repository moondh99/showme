# Meta 사진 이해와 위치 표시 검증

실제 사진에서 질문에 해당하는 물체를 찾고, 반환된 위치를 사진 위에 정확히 표시할 수 있는지 확인합니다. 2026년 11월 1일 첫 실제 호출 10건을 수행했습니다. 결과와 범위는 [검증 결과](RESULTS.md)에 기록했습니다.

## 입력 자료

`inputs/`에 다음 자료를 준비합니다.

- 직접 촬영하거나 재사용이 허용된 실제 작업 사진 3~5장
- 사진별 고유 ID와 담당자의 짧은 설명
- API 호출 전에 작성한 질문·기대 답변·기대 위치와 작성 주체

데모 후보는 행사 접수대의 안내판, 명찰, 현장등록용 트레이입니다. 사진에 없는 절차나 규칙은 담당자 메모로 제공합니다. 첫 검증은 CC0 공개 사진 3장으로 수행했습니다. [출처](photo-sources.json)와 [질문·대략적인 정답 위치](cases.json)를 함께 보관하며, 정답은 응답을 보기 전 Codex가 시각적으로 작성했습니다. 사람 검수 정답 세트는 아닙니다.

질문 전에 정답을 작성합니다. 대상 위치는 이미지 회전을 적용한 동일한 사진을 기준으로 표시합니다. 사진을 자르거나 크기를 바꾸면 모델 입력과 표시 화면의 좌표를 동일한 기준으로 변환합니다.

## 검증 도구 실행

프로젝트 루트에서 실행합니다. Python 3.10 이상을 사용합니다.

```sh
python3 -m pip install -r requirements.txt
python3 scripts/meta_vision.py check
python3 scripts/meta_vision.py run \
  --image experiments/meta-vision/inputs/notepad.jpg \
  --question '메모지 위에 놓인 검은색 펜은 어디 있나요?' \
  --note '검은 펜은 참가자 서명용입니다.' \
  --expected-status found \
  --expected-box 508 535 882 704
```

`check`는 키 존재 여부와 사진 개수만 확인하며 API를 호출하지 않습니다. `run`은 질문 하나당 실제 API를 한 번 호출하고 크레딧을 사용합니다. 자동 재시도는 하지 않습니다. `--prepare-only`를 추가하면 사진 전처리·입력 기록만 수행하고 API는 호출하지 않습니다.

모델에 보내는 사진은 회전을 보정하고 긴 변을 최대 1600픽셀로 줄여 JPEG로 저장합니다. 저장된 `input.jpg`가 실제 전송 이미지이며, `overlay.png`는 그 이미지 위에 좌표를 표시한 결과입니다. 정답 상태·위치는 모델 요청에 포함하지 않습니다.

실행 폴더에는 `run.json`, `input.jpg`, 유효 응답의 `overlay.png`, `report.html`이 저장됩니다. 원래 실행 기록의 `review`는 사람 검토 대기 상태이며, Codex의 대조 결과는 별도 `agent-review.json`으로 남깁니다. 키와 이미지 base64는 기록에서 제거하지만, 사진과 답변 자체는 민감할 수 있어 로컬 보관을 기본으로 합니다.

로컬 도구 검증:

```sh
python3 -m unittest discover -s tests -v
```

8개 테스트는 가짜 API 응답으로 도구의 오류 처리·좌표·회전·로그 처리를 점검합니다. 실제 모델 정확도 평가는 위의 실제 호출 결과와 구분합니다.

## 검증 항목

총 10개 질문으로 시작합니다.

| 유형 | 수 | 기대 동작 |
| --- | --- | --- |
| 명확한 대상 | 5 | 올바른 물체 설명과 위치 반환 |
| 사진에 없는 대상 | 3 | 발견하지 못했다고 응답하고 위치를 만들지 않음 |
| 여러 후보가 있는 모호한 질문 | 2 | 선택지를 제시하거나 추가 질문 |

사진 내용 이해, 담당자 메모의 규칙 반영, 근거가 없는 질문에 대한 처리를 함께 확인합니다. 모델이 스스로 보고한 확신 정도는 정확도의 증거로 사용하지 않습니다.

## 실행 절차

1. `.env.local`의 키와 모델 설정으로 간단한 이미지 요청을 실행합니다.
2. 이미지 ID, 질문, 메모를 전달하고 답변·대상·위치·근거를 받습니다.
3. 응답 구조, 사진 ID, 좌표 범위와 사각형 방향을 검사합니다.
4. 모델에 보낸 동일한 사진 위에 사각형과 대상 이름을 표시합니다.
5. 사람이 작성한 정답과 대조하고 질문별 통과·실패·이유를 기록합니다.
6. 실패 사례를 수정한 뒤 실패 항목과 관련 항목을 재검증합니다.

## 제안된 통과 기준

다음 기준은 첫 기능 검증을 위한 목표이며 측정 결과가 아닙니다.

- 명확한 대상 5개 중 4개 이상에서 답변과 강조 위치가 모두 정확함
- 대상 없음 3개에서 잘못된 물체를 지목하지 않음
- 모호한 질문 2개에서 대상을 임의로 확정하지 않음
- 위치 정답과 예측 사각형의 겹침 비율(IoU)을 참고하되, 사람이 다른 물체를 가리키는지 함께 확인
- 앱이 해석할 수 없는 응답을 정상 결과로 표시하지 않음

이 작은 사례 세트의 통과를 일반적인 정확도나 현장 사용의 보장으로 해석하지 않습니다.

## 결과 기록

`results/` 아래 실행별 폴더에 기록합니다.

- 사용 모델, 실행 시각, 입력 파일 이름과 크기
- 질문, 입력 메모, 사용한 지시문
- 인증 정보와 개인 식별 정보를 제거한 응답
- 실제 응답 시간과 사용량(응답에 제공되는 경우)
- 위치 표시 이미지
- 질문별 판정과 실패 이유

키, 인증 헤더, 원본 이미지의 base64 문자열은 실행 로그에 넣지 않습니다. 실제 입력과 결과는 기본적으로 버전 관리에서 제외되며, 공개 가능한 요약만 이 폴더의 별도 문서로 정리합니다.

## 결과에 따른 개발 결정

- 사진 이해와 위치 표시가 통과하면 사각형 강조를 핵심 기능으로 개발합니다.
- 사진 이해는 되지만 위치 정확도가 부족하면 입력 사진·질문과 위치 보정 방식을 개선하고 재검증합니다. 검증 전에는 자동 위치 표시가 성공했다고 기록하지 않습니다.
- SAM 3.1은 핵심 검증 후 짧게 시험합니다. 물체 윤곽 표시가 안정적일 때 추가합니다.
