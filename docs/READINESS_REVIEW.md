# ShowMe 제출·포트폴리오 완성도 점검

2026년 11월 2일. 목표는 수상 경쟁력과 기획·제품 판단·개발을 함께 보여주는 포트폴리오다. 이 문서의 평가는 내부 판단이며 심사위원 평가나 수상 가능성의 예측값이 아니다.

## 현재 판정

**핵심 흐름이 작동하는 MVP는 갖췄다. 현재 상태를 그대로 최종 제출본이나 수상권 작품으로 추천하지는 않는다.** 사진 입력·AI 초안·설명/위치 보정·전체 승인·조회·질문은 동작한다. 그러나 실제 문제의 중요성을 입증한 자료, 외부 체험 경로, 경쟁 서비스와 구별되는 대표 경험, 최종 영상·제출 패키지가 부족하다.

포트폴리오에는 사용할 만한 기술적 결정과 검증 기록이 있다. 다만 ‘현장 사용자에게 효과를 입증한 출시 제품’으로 표현하면 현재 근거를 넘는다. 사용자 보고상 지금은 관련 실제 운영 경험이나 테스트 참여자를 확보하지 못했다. 이를 AI 사용자 시뮬레이션으로 대체해 실사용 검증이라고 기록하지 않는다.

## 차별성 판단

‘AI가 안내서를 만들고 그 안내서에 질문한다’는 설명만으로는 약하다. Scribe는 절차 기록·단계별 안내서, Guidde는 영상 문서화를 제공한다. Guidde Ask는 출처가 있는 답변과 자료가 부족할 때의 응답 유보까지 공식적으로 설명한다. 경쟁사 전체를 사용성·성능으로 비교한 것은 아니며 공식 제품 설명을 확인한 범위다. [Scribe](https://scribehow.com), [Guidde](https://www.guidde.com), [Guidde Ask](https://www.guidde.com/guidde-ask)

ShowMe의 제품 방향은 **물리적 작업 현장의 사진에서 물체를 선택하고, 담당자가 승인한 업무 규칙과 사진에 보이는 사실을 구분해 안내하는 경험**으로 더 좁히는 것이 타당하다. 이는 차별화 가설이며 세계 최초·유일한 기능이라는 주장이 아니다.

대표 장면 후보는 ‘현장에서 물체를 선택 → 정확한 대상 표시 → 이 물체를 어떻게 써야 하는지 승인 규칙으로 답변’이다. 목적은 모델 수를 늘리는 것이 아니라, 명칭을 모르는 초보자가 물체를 가리켜 질문하는 마찰을 줄이는 것이다.

## 이번 점검에서 새로 실행한 검증

### 질문·근거·위치: 실제 Muse Spark 48회

질문/대화 20개를 먼저 고정하고 2회씩 실행했다. 16개 단일 질문과 4개 2턴 대화로 총 48회다. 실제 공개 사진 3장과 연출 이미지 4장을 사용했다. 모델 프롬프트와 데이터 해시를 기록하고 실행 중 프롬프트를 바꾸지 않았다.

- 유효 응답 48/48, 기대 응답 상태 일치 48/48.
- 근거 부족·대상 없음 16/16에서 확답을 생성하지 않음.
- 위치 기준이 있는 12회 모두 검토된 기준 사각형과 IoU 0.5 이상.
- 서버 질문 처리 함수 기준 중앙값 4.689초, 최근접 순위 방식 P95 7.273초. 전체 브라우저 사용 시간이나 사용자 작업 시간 측정이 아님.
- 192,852토큰. 비용·크레딧 현재 잔액은 조회하지 않음.

이는 **정해진 내부 평가 세트의 결과**다. 기존에 사용한 사진과 승인 사각형을 재사용했으며 예상 상태와 문자열 검사는 Codex가 작성했다. 새 현장 사진 일반화·독립적인 사람 평가·실제 작업 효과를 뜻하지 않는다. 저장된 답변 텍스트도 내부 검토했으며, 모델이 작성한 사진 관찰 문구 자체가 독립 근거가 되는 것은 아니다.

재현 절차·원본 응답·평가 기준: [평가 세트](../evaluations/grounded-qa-v1/README.md).

### SAM 3.1: 실제 4회

노란 트레이, 실제 사진의 검은 펜, 선택한 지점의 검은 펜에서 사각형·윤곽을 받았다. 없는 빨간 가위는 0개로 정상 완료했다. 응답 시간 범위는 2.232~6.163초였다. 공식 파서로 해석하고 브라우저에서 원본 사진 위의 실제 윤곽을 확인했다.

[검증 화면](../experiments/sam-probe/sam-probe.html)은 **서비스 연동 전 기술 검증**이다. 이 검증 시점의 질문 화면은 사각형 강조를 사용했다. 4회 성공만으로 모든 물체에서 정확하거나 사각형보다 사용자에게 낫다고 판단하지 않는다.

Meta 공식 문서는 Muse Spark의 장면 이해와 SAM의 물체 분할을 조합하는 방식을 설명한다. SAM은 업무 규칙을 추론하는 모델이 아니며, 승인된 설명의 권한을 대체하지 않는다. [SAM 개요](https://dev.meta.ai/docs/sam/overview), [프롬프트·지점 지정](https://dev.meta.ai/docs/sam/segmenting)

### 화면에서 바로 고친 부분

점검 전 데모 첫 단계의 질문 제목은 데스크톱에서 약 887px, 390px 모바일에서 약 1,401px 아래에 있었다. 질문 기능이 첫 화면에서 쉽게 발견되지 않았다.

- 상단 질문 바로가기와 질문 영역의 사진 복귀 링크를 추가했다.
- 데스크톱에서 질문을 읽는 동안 원본 사진이 함께 남도록 했다. 모바일에서는 두 영역을 링크로 왕복한다.
- 표시할 사진의 실제 가로·세로를 전달해 이미지 로딩 전 공간을 확보한다. 위치 좌표 기준은 유지한다.
- 모든 단계에 검은 펜 질문을 제안하던 예시를 현재 단계의 승인된 대상 이름으로 바꿨다.
- 응답 뒤 입력창으로 초점을 돌리는 동작을 정밀 포인터 환경에 한정했다. 실제 휴대전화 소프트 키보드 동작은 별도 확인 대상이다.

브라우저에서 링크 왕복, 사진·질문 동시 표시, 모바일 가로 넘침 없음, 크기 속성과 단계별 예시를 확인했다. 실제 API 회귀 질문도 별도로 실행했다. 이 단일 회귀 호출은 위 고정 평가 48회와 분리한다.

SAM 연동은 물체 선택/정확한 강조라는 사용자 경험을 개선할 때 채택한다. 답변을 느리게 하거나 오류가 늘면 비동기 윤곽 표시 또는 기존 사각형으로 되돌릴 수 있어야 한다. 평가 사례를 늘릴 때는 먼저 예상 결과를 고정하고, 조정에 쓴 사례와 최종 검증 사례를 구분한다.

## 크레딧 사용 원칙

사용자가 150달러 지원을 받았고 추가 API 사용을 허용했다. 현재 잔액이나 계정의 실제 사용 요금은 별도로 확인하지 않았다. 이번에는 평가 48회, SAM 4회, UI 회귀 1회로 추가 53회를 실행했다. ‘돈을 더 썼다’를 성과로 삼지 않는다. 다음 지출은 새로운 실제 사진의 실패 찾기, 물체 선택·윤곽의 오류/지연 비교, 동시 접속 시연 안정성처럼 결정에 필요한 실험으로 한정한다.

## 포트폴리오에 사용할 수 있는 사실

- 사진만으로 업무 규칙을 만들지 않도록 담당자 메모와 승인본을 분리했다.
- 사진 좌표가 넓게 잡히는 사례를 근거로 수동 위치 검토와 승인을 넣었다.
- 초안 변경이 기존 참여자 화면을 바꾸지 않도록 승인 시점의 내용을 고정했다.
- 근거 문구·대상 없음·대상 모호함·정보 부족을 구분하고 실제 API로 회귀했다.
- 확인 질문 뒤 답변을 지나치게 유보하던 사례를 발견해 원래 질문과 선택 답변의 연결을 개선했다.
- 정해진 내부 평가와 실제 사용자 효과를 구분했다.

사용자 질문 감소율·작업 시간 단축률·현장 도입 수·수상 여부는 아직 쓸 수 있는 성과가 아니다. 이런 수치를 만들어 넣지 않는다.


## 같은 날 후속 구현 완료: 물체 선택 제품 연결

위 점검 당시 기술 검증 화면에만 있던 SAM을 이후 사용자 요청에 따라 실제 학습 화면에 연결했습니다. 사진 클릭 → SAM 윤곽 → 승인 문구 근거 답변, 선택 해제·재선택·키보드/모바일·모호함 확인·정보 부족 유보를 구현했습니다. 새 실제 Meta 호출 12회(SAM 5·Muse 7), 자동 검사 48개(Python 45·JS 3), 브라우저 전체 흐름과 서버 재시작을 검증했습니다. 기존 승인본 3개는 변경되지 않았습니다. [상세 결과·시연 순서·제약](SELECTION_RESULTS.md).

이 업데이트로 물체 선택의 제품 연결 항목을 완료했습니다. 알려진 AI 연출 사진의 내부 검증이며 실제 현장 사용자 효과나 일반 정확도를 증명하지는 않습니다. 영속 배포·외부 체험·재현 환경·최종 영상·제출 준비는 계속 남아 있습니다.
