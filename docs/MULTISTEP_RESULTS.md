# ShowMe 다단계 안내서 구현과 검증

2026년 11월 1일, 사진 한 장의 흐름을 **최대 6단계의 입력·순서 편집·AI 생성·검토·전체 승인·학습**으로 확장했습니다. 실제 Meta API와 로컬 브라우저에서 6단계 전체 흐름을 확인했습니다. 학습자 질문·답변과 외부 배포는 아직 구현하지 않았습니다.

## 구현한 동작

- JPEG·PNG·WebP 사진을 여러 장 선택해 등록합니다. 안내서당 최대 6단계이며 각 사진은 10MB 이하입니다.
- 단계 카드를 선택해 사진·메모·설명·강조 영역을 편집합니다. 다른 단계로 이동할 때 현재 입력을 저장합니다.
- 앞뒤 화살표로 순서를 바꿉니다. 사진·설명·강조 영역은 고유 단계 ID를 따라 함께 이동합니다.
- 현재 단계만 AI 초안을 생성하거나, 설명이 없는 단계를 순차 생성합니다. 이미 설명이 있는 단계는 일괄 생성에서 건너뛰며 수동 수정은 보존합니다.
- 설명이나 강조 영역을 바꾸면 해당 단계의 검토를 해제합니다. 순서를 바꾸면 위치가 달라진 단계의 검토를 해제합니다. 안내서 제목·목표 변경은 모든 단계의 검토를 해제합니다.
- 모든 단계의 필수 설명이 채워지고 검토가 끝나야 전체 승인본을 만듭니다. 저장 순서와 설명·사진·강조 영역을 한 번에 고정합니다.
- 학습 화면에서 단계 선택·이전·다음·단계별 완료 표시·전체 완료를 제공합니다. 승인본별로 현재 단계와 완료 상태를 같은 브라우저에 보관합니다.
- 초안에서 단계 삭제·순서 변경·내용 수정을 해도 기존 승인본과 해당 사진은 유지합니다.

## 실제 API와 브라우저 검증

‘사진으로 준비물 확인하기 · 6단계 검증’ 안내서를 브라우저에서 만들었습니다. 실제 사진 3종을 두 번씩 사용해 6개 업로드와 독립된 메모·설명·위치 연결을 검증했습니다. 원본 3종은 이전 실험에서 확보한 CC0 공개 사진이며 새로 촬영한 연속 작업 과정은 아닙니다. 실제 현장 작업의 효과를 입증하는 사용자 실험과 구분합니다.

| 실제 확인한 흐름 | 결과 |
| --- | --- |
| 사진 6장 한 번에 등록 | 각기 다른 ID를 가진 6단계 저장, 추가 버튼 비활성화 |
| 단계별 다른 메모 입력 | 단계 이동 후에도 메모 저장·연결 유지 |
| 미작성 단계 일괄 생성 | 실제 Meta API 6건 성공, 성공한 단계별 결과 저장 |
| 설명·강조 위치 검토 | 화면 설명 수정, 화면·검은 펜 좌표 보정, 6단계 검토 완료 |
| 검토 후 첫 두 단계 순서 교환 | 검토 상태 6/6 → 4/6, 전체 승인 버튼 비활성화 |
| 변경 단계 재검토·전체 승인 | 검토 6/6 복원 후 하나의 승인본과 링크 생성 |
| 학습 화면에서 모든 단계 이동 | 바뀐 순서대로 각각의 사진·설명·강조 영역 표시 |
| 6단계 완료 표시·새로고침 | 현재 단계와 완료한 6단계가 복원됨 |
| 생성 완료 후 일괄 생성 버튼 재선택 | 기존 설명을 유지한다는 안내, 추가 API 호출 없음 |
| 서버 종료·재실행 | 승인본과 사진 6개 모두 복원 |
| 390×844 휴대전화 화면 | 가로 넘침 없음, 단계 이동·완료 상태 유지 |

### 실제 모델 호출 기록

모델은 `muse-spark-1.3`이며 이번 다단계 검증의 실제 생성 호출은 6건입니다. 모델과 요청 형식은 첫 구현의 단계 생성 경로를 재사용합니다.

| 지표 | 측정값 |
| --- | --- |
| 단계별 응답 시간 | 5.540 / 7.209 / 5.310 / 4.636 / 6.734 / 5.912초 |
| 평균 응답 시간 | 5.890초 |
| 모델 호출 시간 합계 | 35.341초 |
| API 보고 입력 토큰 | 14,630 |
| API 보고 출력 토큰 | 7,683 |
| API 보고 합계 토큰 | 22,313 |

호출 시간 합계는 개별 요청 측정값의 합이며 사진 입력·검토·승인을 포함한 전체 작업 시간과 다릅니다. 토큰 수로 실제 청구 금액이나 잔여 크레딧을 추정하지 않았습니다. 브라우저 콘솔의 오류·경고는 없었습니다.

## 실제 서버에서 추가로 확인한 규칙

1. 7번째 단계를 포함한 저장 요청은 HTTP 422로 거절되고 저장 버전은 유지됩니다.
2. 승인 후 초안에서 순서를 바꿔도 기존 승인본의 순서는 유지됩니다. 검증 뒤 작성 화면은 원래 승인 순서로 복원했습니다.
3. 검토가 풀린 상태에서 강제로 승인 요청을 보내도 HTTP 422로 거절됩니다.
4. 승인본의 사진 6개는 읽을 수 있지만 해당 승인본에 없는 단계의 사진 요청은 HTTP 404입니다.
5. 로그인하지 않은 초안 조회는 HTTP 401입니다.
6. 기존 1단계 승인 링크를 계속 열 수 있습니다. 이전 승인본의 저장 JSON 해시가 변경 전과 동일합니다.

## 데이터와 호환성

새 안내서는 순서가 있는 `steps` 배열로 저장합니다. 기존 단일 `step` 문서는 조회 시 1개짜리 배열로 변환하며, 승인 원문을 다시 쓰지 않습니다. 기존 단일 승인본의 내용·사진 URL도 유지합니다.

단계별 사진 URL은 승인본의 단계 ID 목록에서 대상을 찾은 뒤 반환합니다. 초안의 현재 순서나 임의의 사진 ID를 조회하지 않습니다. 초안 수정은 버전 비교를 사용하고 전체 승인은 SQLite 트랜잭션으로 고정합니다.

변경 전 SQLite 백업은 `state/backups/before-multistep.sqlite3`, 기존 승인 원문 해시는 `state/evidence/legacy-snapshot-hashes.json`에 보관했습니다. 원본 사진 파일은 변경하지 않았습니다.

## 자동 테스트

22개가 통과했습니다. 앱 통합 테스트 14개와 기존 사진 검증 도구 테스트 8개입니다. 추가한 테스트는 6단계 승인·순서 교환·단계 삭제·7번째 단계 및 중복 ID 거절·수정 대상만 재검토·전체 목표 변경·생성 실패 시 앞 단계 보존·기존 단일 문서 호환성을 확인합니다. 자동 테스트는 가짜 모델 응답을 사용하며 위 실제 6건 호출과 구분합니다.
