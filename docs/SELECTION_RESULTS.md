# 사진 직접 선택·SAM 윤곽·승인 근거 답변

2026년 11월 2일 KST. 기술 검증 화면에 있던 SAM을 실제 학습 화면에 연결했습니다. 사진 등록·수정·승인 흐름은 유지하며, 현재 승인본의 사진에서 물체를 직접 선택해 질문할 수 있습니다.

## 구현한 경험

1. ‘사진에서 물체 선택’ → 물체 가운데 클릭/탭 또는 방향키·Enter/Space.
2. SAM 3.1의 실제 윤곽을 파란색으로 표시하고 선택한 대상을 질문에 연결.
3. Muse Spark 1.3이 현재 사진과 현재 단계의 승인된 설명·완료 확인을 근거로 답변. 용도·절차는 승인 문구 인용이 있어야 답함.
4. 모호하면 확인 질문, 근거가 없으면 ‘모르겠습니다’. 선택 해제·재선택·Esc 취소·과거 질문의 선택 복원을 지원.

SAM은 위치, Muse Spark는 대상과 승인 문구의 관계를 처리합니다. 윤곽 자체는 업무 규칙의 증거가 아닙니다. 사진과 승인 내용에 관한 AI 답변은 추가 담당자 승인을 받은 문장이 아니라는 표시를 유지했습니다.

## 실제 API 검증

기존 행사 접수대 안내서 2단계의 AI 연출 사진으로 **새 호출 12회: SAM 5회, Muse Spark 7회**를 실행했습니다. 이전 SAM 실험 4회·48문항 평가는 이번 횟수에 포함하지 않습니다. 실제 행사 사진이나 외부 사용자 테스트는 아닙니다.

| 사례 | 결과 |
| --- | --- |
| 검은 펜 클릭 → “이 물체는 무엇에 쓰나요?” | 참가자 서명용, 승인 설명 인용 |
| 파란 펜 클릭 → 같은 질문 | 운영자 메모용, 승인 설명 인용 |
| 파란 펜 → “참가자 서명을 받아도 되나요?” | 아니요, 검은 펜 사용. 두 승인 문구 인용 |
| 파란 펜 → 브랜드·구매 시점 | 정보 부족, 모른다고 응답 |
| 2단계 상단 명찰 영역 선택 → 누구의 명찰 용도인지 질문 | 현재 단계에 규칙이 없으므로 정보 부족. 3단계의 규칙을 가져오지 않음 |
| 선택 해제 → “이 펜은 무엇에 쓰나요?” | 검은/파란 펜을 구분하는 확인 질문 |
| 서버 재시작 후 모바일 파란 펜 클릭 → 용도 질문 | 윤곽 생성과 승인 근거 답변 정상 |
| 키보드로 검은 펜 선택(740,540) | 실제 SAM 윤곽, 처리 중 다른 단계에 표시되지 않음 |

선택 5회 모두 마스크 반환을 확인했습니다. 질문 7회는 근거 답변 4회·정보 부족 2회·확인 질문 1회로 기대 상태를 확인했습니다. 상단 명찰 영역의 분할은 대상 정체의 정확성을 독립 평가한 사례가 아니며, 해당 질문은 규칙 부족 유보를 확인하는 데 사용했습니다.

서버 내부 측정(네트워크 전체 왕복과 브라우저 렌더링 제외): SAM 1.207~4.526초, 평균 2.853초. Muse 3.131~5.894초, 평균 4.819초. Muse 보고 사용량 29,249토큰. SAM 응답은 `images_processed=1`이며 토큰 수 0으로 보고되어 비용 0달러를 뜻하지 않습니다. 실제 청구 비용은 별도 조회하지 않았습니다.

## 자동 검사와 브라우저

- Python 45개 통과: 승인본/단계/사진 격리, 선택 위조·만료, 확인 대화의 선택 일치, 승인 근거 없는 답변 유보, 좌표 형식·윤곽 검증, 미발견·시간 초과·재요청 슬롯 해제·빈도 제한, 기존 질문 테이블 마이그레이션, 실제 SAM 이벤트 형식 파싱, 모델 전달 자료 제한.
- JavaScript 3개 통과: 표시 크기별 좌표 변환·사진 밖 클릭 제외, 키보드 이동/경계/확정/취소, 원본 좌표 윤곽 표시. 두 JS 파일 구문 검사 통과.
- 브라우저: 클릭 → SAM → 질문 → 승인 인용 답변, 근거 부족·확인 질문, 승인 사각형 복귀, 과거 선택 복원, Esc 취소, 키보드 선택을 확인.
- 선택/질문 처리 중 다른 단계로 이동해도 결과는 원래 단계에만 연결됨.
- 390px 모바일 설정에서 실제 클릭 → 윤곽 → 질문 완료. 문서 폭·내용 폭 모두 375px(스크롤바 제외)로 가로 넘침 없음. 기본 화면 크기로 복원.
- 서버를 잠시 중단한 상태에서 질문 전송: 실패 안내와 입력 보존 확인. 서버 재시작 후 같은 승인본을 읽고 모바일 실제 호출을 완료. 정상 흐름의 브라우저 경고·오류 로그 없음.
- 기존 승인본 3개의 저장 내용 SHA-256이 구현 전후 동일. 스키마 변경 전 DB 백업 보관. 코드·문서·테스트 자료의 키/비밀번호 일치 검사에서 노출 없음.

미발견·시간 초과·잘못된 마스크·만료·위조 등 실패 조건은 통제된 자동 검사입니다. 실제 공급자에서 각 실패를 강제로 발생시켜 검증한 것은 아닙니다.

## 저장과 경계

선택은 임의 토큰으로 서버에 저장되며 승인본·단계·사진과 24시간 유효 기간을 확인합니다. 질문에서 클라이언트가 보낸 윤곽이나 좌표를 신뢰하지 않습니다. 확인 대화도 동일한 선택에만 연결됩니다. 선택·질문은 분당 10회·시간당 60회 제한을 공유하고 초안 생성까지 합해 동시 2개로 제한합니다. 자동 API 재호출은 하지 않습니다.

공식 `meta-sam-parser==0.1.0`으로 스트림을 파싱하고, 원본 크기·마스크 범위·선택 픽셀 포함 여부를 검사합니다. 제한된 SVG path만 화면에 전달하며 인증 헤더·키·이미지 base64·원본 공급자 오류는 표시하지 않습니다. 승인된 설명은 인용의 실제 부분 문자열 여부를 검사하고, 선택 질문이 사진 근거만 제시하면 서버가 정보 부족으로 바꿉니다. 인용이 정확해도 답변 전체의 의미가 옳다는 보장은 없어 다양한 사진·가림·유사 물체 평가가 후속으로 필요합니다.
