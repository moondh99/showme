후속 상태: R01·R03·R08은 이후 [수정·검증](RECOVERY_FIXES_RESULTS.md)했다. 이 문서는 수정 전 재평가 기록이다.

평가 대상 소스: `5c302fd`. 이번 작업은 평가와 문서 상태 정정이며 소스 코드는 수정하지 않았다. 기존 시연 사진과 저장된 실제 SAM 선택 결과를 사용했다. 독립 현장 사진·사람 평가가 아니다.

## 판정

로컬 MVP의 핵심 흐름은 구현돼 있다. 전체 제품·최종 제출 완성으로 판단하지 않는다. 이전 실패 사례를 고친 것과 새로운 표현·문맥에서도 신뢰할 수 있다는 것은 별개의 검증이다. 특히 자동 질문 분류와 승인 문장 축약은 여전히 제한된 키워드에 의존한다.

| 항목 | 판정 | 확인 근거 |
|---|---|---|
| 질문 모드 | 부분 해결 | 빠른 질문의 목적이 다음 일반 질문에 남는 기존 버그는 해결. 새 자연어 질문이 다른 이유로 잘못 분류됨 |
| 보완 질문 누락 | 기존 결함 해결 | 정상 100개 이후·20개 초과·24시간 만료·재시작·이관·완료/복원 회귀 통과. 성공한 재확인의 최초 거절은 미처리 목록에 남는 별도 문제 발견 |
| 대상별 답변 | 부분 해결 | 실제 파란/검은 펜 선택에서 각각 올바른 승인 문장. 뒤따르는 금지 문장 보존은 통제된 반례에서 실패 |
| 모바일 안내 순서 | 검사 범위에서 해결 | 390×844 Chrome에서 사진 → 승인 설명·완료 → 질문. 실제 휴대전화의 키보드·현장 사용 검증은 아님 |

## 실제 API·브라우저 재현

호출 전 기대 결과를 `state/evidence/postfix-audit-plan.json`에 고정했다. 새 Muse Spark 호출은 4회이며 신규 SAM 호출은 없다.

1. 일반 입력에서 ‘파란색 펜은 운영자 메모 전용인가요?’를 전송했다. 승인 설명에 답이 있지만 `intent=appearance`, `status=insufficient_information`으로 거절했다. 색이라는 단서에 반응하고 ‘전용’이라는 용도를 놓치는 분류가 원인이다.
2. 같은 화면의 ‘승인 규칙에서 다시 확인’을 눌렀다. `intent=procedure`로 ‘파란 펜은 운영자 메모용으로만 사용합니다.’를 반환했다. 사용자가 한 번 더 조작해야 한다.
3. 저장된 실제 파란 펜 SAM 선택에 ‘선택한 물체는 무엇에 쓰나요?’를 물었다. 파란 펜 운영자 메모 문장과 일치했다.
4. 저장된 실제 검은 펜 SAM 선택에 같은 질문을 보냈다. ‘참가자 서명에는 검은 펜을 사용합니다.’와 일치했다.

첫 거절은 `learning_gaps`의 미처리 목록에 남아 있고, 같은 질문의 재확인 성공은 이를 해결 처리하지 않는다. 누락 문제와 반대로, 작성자가 필요 없는 보완을 검토하게 되는 문제다.

모바일 측정: 설명 시작 y=827px, 완료 제어 y=1,044px, 질문 y=1,276px. 작업 안내가 질문보다 먼저 나온다. 문서 가로 폭은 화면을 넘지 않았다. 기존 승인본 3개의 저장 내용 해시는 변하지 않았다.

## 통제된 문맥 보존 반례

승인 설명을 ‘파란 펜은 운영자 메모용입니다. 참가자에게 건네지 않습니다.’로 두고 첫 문장만 인용한 응답을 검증기에 입력했다. 검증 결과는 첫 문장만 남겼다. `approved_excerpt`의 조건·예외 키워드 검사에 걸리지 않는 뒤 금지 문장은 보존되지 않는다.

이것은 검증기와 인용 축약의 통제된 검사이며, 실제 모델이 위 잘못된 답변을 생성했다는 증거는 아니다. 원문 열기 기능은 남아 있지만 기본 답변에서 중요한 제한을 빠뜨릴 가능성을 없애지는 못한다.

## 자동 검사와 증거

- Python 64개 + JavaScript 5개 = 69개 재통과. 주로 로컬 저장·권한·요청 계약과 모델 대체 응답을 검사한다. 69회의 유료 API 호출을 뜻하지 않는다.
- 실제 호출·응답·보완 목록 상태·대상 일치·승인본 보존: `state/evidence/postfix-audit-results.json`.
- 실제 거절 화면: `state/evidence/postfix-audit-mode-phrase.jpg`.
- 재확인 후 모바일 화면: `state/evidence/postfix-audit-recovery-mobile.jpg`.
- 증거 파일은 로컬 `state/`에 있으며 버전 관리 대상이 아니다.

## API 잔액과 구현 범위

잔액 149달러는 사용자 보고이며 제공자 청구 화면을 직접 조회하지 않았다. 단가·무료 처리·청구 반영 시점·정확한 누적 비용을 추정하지 않는다.

이번 검사 시작 시 남아 있던 서로 다른 호출 기록은 고정 평가 Muse 48회, 서비스 질문 Muse 42회, 서비스 SAM 선택 10회였다. 최소 100개의 보존된 실제 호출 기록을 확인했지만, 이는 전체 기간의 호출 수나 청구 원장이 아니다. 이번 4회는 별도다.

사진·메모의 AI 초안 생성, 질문 답변, SAM 분할은 실제 Meta API에 연결돼 있다. 사진 편집·승인·단계 이동·학습 진행·원문 검색·보완 목록 등 대부분의 앱 기능은 로컬 처리여서 지원금을 직접 소모하지 않는다. 잔액으로 기능 완료를 판단하거나 잔액 소진을 위해 호출할 근거는 없다.

미완료 범위는 구분한다.

- 개발 보완: 자동 질문 분류, 금지·조건 문맥 보존, 재확인 성공과 보완 목록의 연결.
- 후속 기능: 전 단계 AI 검색은 미구현이며 현재는 승인 원문의 키워드 검색이다.
- 검증·배포·제출: 실제 작업 시나리오, 독립 사진 평가, 사용자 관찰, 외부 영속 배포, 최종 영상·제출 패키지(I11~I15).
- 실시간 영상·음성 입력·작업 완료 자동 판정은 첫 버전 약속 범위에 포함하지 않았다.

지원금 사용액보다 더 큰 약점은 평가가 익숙한 시연 사진과 제한된 질문에 집중돼 있다는 점이다. 새 현장 자료와 표현을 사용한 독립 평가 전에는 제품의 일반 정확성이나 실사용 효과를 주장할 수 없다.
