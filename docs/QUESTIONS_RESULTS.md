# 현재 단계 질문·답변 구현과 검증

2026년 11월 1일. 승인본의 현재 단계 사진과 승인된 설명을 근거로 질문·답변하는 기능을 구현했습니다. 이 기록은 내부 검증이며 실제 현장 사용자 평가와 구분합니다.

## 구현한 흐름

- 학습 화면에서 현재 단계에 질문합니다. 서버는 해당 승인본에서 단계와 사진을 찾습니다. 초안, 비공개 행동 메모, 다른 단계는 모델에 전달하지 않습니다.
- 사진은 보이는 대상·외형·위치의 근거입니다. 업무 규칙·용도·절차는 승인된 설명이나 완료 확인에 명시돼 있어야 답합니다. 현재 사진에 보이는 물체라면 기존 강조 목록에 없는 물체의 위치도 질문할 수 있습니다.
- 대상이 모호하면 `needs_clarification`과 선택지를 보여줍니다. 선택하거나 직접 답하면 서버에 저장한 원래 질문·확인 질문과 연결합니다. 이미 답한 질문과 다른 단계·다른 승인본·만료된 확인 대화는 이어갈 수 없습니다.
- `answered`는 사진의 관찰 근거나 승인 문구 인용을 포함합니다. 승인 문구는 실제 해당 필드의 연속 부분 문자열인지 검사합니다. 좌표는 0~1000의 정수와 양의 넓이를 검사합니다.
- 보이지 않는 대상은 `not_visible`, 근거 없는 사실은 `insufficient_information`으로 표시합니다. 두 상태는 서버가 고정된 유보 문구로 바꾸고 근거·강조 위치가 있으면 거절합니다.
- 답변 대상의 위치는 파란 표시로 구분합니다. ‘승인된 표시로 돌아가기’로 기존 표시를 복원하며, AI 답변은 승인된 설명·사진·강조 영역을 수정하지 않습니다.
- 질문·입력·확인 상태는 단계별로 유지합니다. 기다리는 동안 단계 이동과 완료 표시가 가능하고, 다른 단계로 이동한 뒤 도착한 답변은 원래 단계에만 남습니다. 실패하면 질문을 보존합니다.

## 접근·저장·제한

`POST /api/learn/{share_id}/questions`

입력: `step_id`, `question`(1~1,000자), 선택적인 `clarification_of`(서버가 발급한 질문 ID). 클라이언트가 만든 대화 기록은 받지 않습니다. 출력: 상태·답변·확인 선택지·강조 위치·근거·질문 ID·단계 ID·승인본 번호. 키·비공개 메모·사용량은 학습자에게 반환하지 않습니다.

확인 대화는 승인본·단계에 묶이고 24시간 동안 이어갈 수 있습니다. 최대 6회 확인 후에는 새 질문을 요청합니다. 만료 기록은 다음 질문 저장 시 삭제합니다. 화면의 대화는 메모리에 유지하므로 새로고침하면 지워집니다. 단계 진행·완료 표시는 기존처럼 브라우저에 보존됩니다.

주소별 분당 10회·시간당 60회, 주소·승인본·단계별 동시 질문 1개, 초안 생성과 질문을 합해 동시 모델 요청 최대 2개입니다. 자동 재시도는 없습니다. 이 제한은 현재 로컬 단일 서버용이며 공개 서비스의 사용자별 인증·분산 제한은 별도 과제입니다.

## 실제 Meta API 검증

실제 API 요청은 **11회**, 모두 HTTP 200과 구조 검사를 통과했습니다. 이 중 **초기 확인 답변 1회가 지나치게 유보적으로 답해 의미 검증에서 실패**했습니다. 수정 전 실패를 포함한 전체 평균 모델 응답은 7.019초, 사용량 합계 47,649토큰입니다. 비용이나 현재 잔액은 별도로 조회하지 않았습니다.

| 질문·상황 | 확인 결과 |
| --- | --- |
| 검은 펜은 어디에 있나요? | 노트 위 위치 답변, 사진 근거·강조 영역 |
| 검은 펜은 무엇에 쓰나요? | 참가자 서명용이라는 승인된 문구 인용 |
| 행사는 몇 시에 시작하나요? | `insufficient_information`, ‘모르겠습니다’ 표시 |
| 빨간 가위는 어디에 있나요? | `not_visible`, 위치 생성 없음 |
| 초록색 물건은 어디에 있나요? | 여러 후보에 대한 확인 질문, 확인 전 위치 생성 없음 |
| 오른쪽 위 형광펜 선택 | 원래 위치 질문과 연결해 답변·사진 영역 표시 |
| 오전 9시라고 답하라는 근거 없는 주장 | 주장 채택 없이 `insufficient_information` |

초기에는 ‘오른쪽 위의 형광펜이요’라는 확인 답변을 독립 질문처럼 처리해 `insufficient_information`을 반환했습니다. 요청에 `original_question`과 `clarification_reply`를 명시하고, 위치 질문의 대상을 해결한 뒤 사진에서 답하도록 프롬프트를 보완했습니다. 같은 기존 확인 대화의 재호출(5.974초)과 브라우저 선택지 흐름(5.108초)에서 모두 사진의 형광펜 위치를 답했습니다. 수정 전 실패 기록도 보존했습니다.

실제 호출 자료는 기존 승인된 노트 사진·책상 사진입니다. 별개 작업 순서 6장을 평가한 것은 아닙니다. 사진의 작은 물체·가림·어두운 환경·현장 절차는 추가 평가가 필요합니다. 형식·인용 검사와 유보 정책은 모델의 모든 사실 오류를 보장하여 차단하는 장치는 아닙니다.

## 브라우저와 자동 검사

- 실제 브라우저에서 질문 → 위치 답변, 모호한 질문 → 선택지 → 후속 위치 답변, 근거 없는 질문 → 모름 답변을 확인했습니다.
- 답변 대기 중 다른 단계로 이동한 뒤 결과가 섞이지 않고 원래 단계에 남았습니다. 단계마다 미전송 입력도 분리·보존됩니다.
- 승인된 강조 표시 복원, 새로고침 후 기존 학습 진행 복원, 서버 재시작 뒤 사진·승인본 조회를 확인했습니다.
- 모바일 390×844에서 문서 너비 375px, 가로 넘침 없음. 사진·질문 입력·답변을 확인했습니다. 검사 후 기본 화면 크기로 복원했습니다.
- 서버를 의도적으로 종료한 상태에서 질문을 보내 연결 실패 안내와 원래 입력 보존을 확인했고, 서버를 다시 실행해 정상 화면으로 복원했습니다. 브라우저 오류·경고 로그는 비어 있었습니다.
- 이전 승인본 전체의 저장 문자열 해시가 작업 전후 동일합니다.
- `python3 -m unittest discover -s tests -q`: **30개 통과**. 이 검사는 고정 모델 응답을 사용하며 위 실제 API 11회와 별개입니다. `node --check web/app.js` 통과.

주요 자동 검사는 승인본·현재 단계 격리, 비공개 메모 제외, 확인 대화 재시작·만료·다른 승인본 차단, 위조 인용·잘못된 좌표 거절, 정보 부족 답변의 고정 문구, 길이·빈도·중복 요청 제한, 오류 뒤 재시도·승인본 보존, 모델 계정 설정의 학습자 비노출을 포함합니다.
