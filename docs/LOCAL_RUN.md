# ShowMe 로컬 실행

학습 화면에 Pinboard 디자인을 적용했습니다. 사진과 노란 승인 메모를 함께 보고, 물체 선택·단계 이동·질문을 이어갑니다. 모바일에서는 사진 → 승인 메모·완료 확인 → 질문 순서입니다. [디자인 적용·검증 결과](PINBOARD_RESULTS.md)와 [답변 동작 검증](REAUDIT_FIXES_RESULTS.md)을 참고하세요.

사진 최대 6장으로 안내서 입력·순서 편집·AI 초안 생성·단계별 검토·전체 승인·학습·현재 단계 질문까지 사용할 수 있습니다. 이 서버는 이 컴퓨터의 `127.0.0.1`에서만 접속됩니다. 외부 배포와 다른 기기에서의 원격 접속은 아직 설정하지 않았습니다.

## 시작

프로젝트 루트에서 실행합니다. Python 3.10 이상을 사용합니다.

```sh
python3 -m pip install -r requirements.txt
python3 scripts/serve.py
```

[ShowMe 작업 공간](http://127.0.0.1:8765)을 엽니다. `.env.local`의 `MODEL_API_KEY`를 서버에서 읽으며, API 키는 화면에 입력하지 않습니다.

작성자 비밀번호는 `.env.local`의 `SHOWME_AUTHOR_PASSWORD`가 있으면 그 값을 사용합니다. 따로 설정하지 않으면 첫 실행 시 `state/author-password.txt`에 생성합니다. 이 파일은 이 컴퓨터에서만 보관하며 버전 관리에서 제외합니다. 로그인은 하루 동안 유지됩니다.

## 사용 순서

1. 작성자 비밀번호로 작업 공간을 엽니다.
2. 새 안내서를 만들고 ‘사진 추가’에서 최대 6장을 선택합니다. ‘샘플 사진 추가’로 기존 검증 사진을 사용할 수도 있습니다.
3. 사진 카드의 앞뒤 화살표로 작업 순서를 정합니다. 안내서 제목·목표와 각 단계의 행동 메모를 적습니다. 단계 전환 시 현재 입력을 저장합니다.
4. ‘이 단계 AI 초안 만들기’ 또는 ‘미작성 단계 AI 초안 만들기’를 실행합니다. 일괄 생성은 설명이 없는 단계만 순서대로 처리하며, 이미 수정한 설명은 덮어쓰지 않습니다.
5. 단계마다 설명·완료 확인·강조 위치를 확인해 수정하고 ‘이 단계 검토 완료’를 실행합니다. 필요한 정보가 부족하다는 질문은 메모나 설명에 보완합니다.
6. 모든 단계의 검토가 끝나면 ‘전체 승인본 만들기’를 실행하고 학습 링크를 엽니다. 로그인 없이 해당 승인본의 단계들을 순서대로 볼 수 있습니다.
7. 각 단계의 ‘사진과 설명에 질문하기’에서 질문합니다. 확인 질문이 나오면 대상을 선택하거나 직접 답합니다. 답변의 위치와 근거를 보고, 필요하면 ‘승인된 표시로 돌아가기’를 선택합니다.

단계 내용을 수정하면 해당 단계의 검토가 해제됩니다. 순서를 바꾸면 위치가 달라진 단계들을 다시 검토해야 합니다. 제목·목표 변경은 전체 검토를 해제합니다. 기존 승인본은 바뀌지 않으며 새로 검토·승인하면 새로운 링크가 만들어집니다. 일괄 생성이 중간에 실패해도 앞서 생성한 결과는 저장되어 있으며, 다시 실행하면 미작성 단계부터 진행합니다.

## 저장 위치와 범위

- `state/showme.sqlite3`: 초안, 승인본, 로그인 세션, 질문·확인 대화
- `state/photos/`: 회전·크기 보정을 마친 사진
- `state/author-password.txt`: 작성자 비밀번호를 별도 설정하지 않았을 때 생성
- `state/evidence/`: 첫 구현의 실제 동작 검증 기록과 화면

`state/`는 삭제하면 저장한 안내서·사진·로그인 정보가 함께 사라지므로 유지합니다. 서버를 종료했다 다시 실행하는 것은 데이터를 지우지 않습니다.

학습 화면에서 이전·다음 또는 단계 이름을 선택해 이동하고 완료를 표시합니다. 현재 단계와 완료 목록은 승인본별로 같은 브라우저에서 복원됩니다. 같은 탭에서 새로고침하면 승인본과 단계별로 최근 질문 8개, 미전송 입력, 물체 선택을 최대 24시간 동안 복원할 수 있습니다. 응답을 받지 못한 질문은 입력란에 남고 직접 다시 보내야 합니다. ‘AI 답변의 한계·대화 보관 안내’에서 이 단계의 화면 기록을 지울 수 있습니다. 확인 대화는 서버 질문 ID로 24시간 동안 이어갈 수 있고 만료 기록은 다음 질문 저장 시 삭제합니다. 링크를 받으면 해당 승인본을 읽을 수 있는 방식이며 개별 학습자 계정이나 접근 회수 기능은 없습니다. 공개 배포 전에는 외부 호스트·HTTPS·영속 디스크 설정과 학습자별 인증·요청 제한을 추가 검토합니다. 현재 질문은 주소별 분당 10회·시간당 60회로 제한하며 생성과 질문을 합해 동시 2개만 처리합니다.

## 사진 속 물체 선택

‘사진에서 물체 선택’을 누르고 사진 속 물체의 가운데를 누르면 실제 SAM 3.1이 파란 윤곽을 표시합니다. ‘이 물체는 무엇에 쓰나요?’처럼 질문하면 현재 단계의 승인된 설명·완료 확인에서 온전한 승인 문장을 제시합니다. 조건·예외가 감지되면 전체 문맥을 유지하고, 답변 아래에서 전체 원문도 열 수 있습니다. 사진·윤곽만으로 업무 규칙을 추정하지 않습니다. 대상이 모호하면 확인하고 근거가 없으면 유보합니다.

방향키로 지점을 옮기고 Enter/Space로 선택할 수도 있습니다. Shift+방향키는 크게 이동하며 Esc는 취소합니다. ‘다른 물체 선택’으로 바꾸고 ‘선택 해제’로 승인된 사각형 표시로 돌아갑니다. 과거 답변의 ‘이 질문의 선택 다시 보기’로 당시 대상을 복원할 수 있습니다. 선택 실패·통신 실패 시 다시 시도할 수 있고 승인된 사진·설명은 계속 읽을 수 있습니다.

선택은 승인본·단계·사진에 묶여 서버에 저장되며 24시간 유효합니다. 다음 선택 저장 시 만료 기록을 정리하고 확인 대화도 같은 선택 안에서만 이어집니다. 브라우저 복원은 위의 탭별 범위를 따릅니다. 서버 재시작 뒤에도 기존 데이터 디렉터리를 사용하면 저장된 선택과 승인본을 불러올 수 있습니다. 질문과 선택을 합해 주소별 분당 10회·시간당 60회, 초안 생성까지 합해 동시 2개로 제한합니다.

`requirements.txt`에 공식 `meta-sam-parser` 의존성이 포함됩니다. 키는 기존 `.env.local`을 사용하며 브라우저에는 전달하지 않습니다. [실제 API·브라우저 검증 결과](SELECTION_RESULTS.md).

## 재평가 수정 후 사용 흐름

사진 다음에 승인 설명과 완료 확인을 먼저 읽습니다. 막히면 물체를 선택해 ‘무엇에 쓰나요?’ 또는 ‘색·모양·위치 알려주세요’를 누르거나 직접 질문합니다. 빠른 질문은 해당 요청에만 적용되므로 사진 질문 뒤 일반 입력으로 업무 규칙을 물어도 승인 설명을 확인합니다. 확인 대화에서 다른 질문으로 바꾸려면 ‘새 질문으로 시작’을 누릅니다.

업무 규칙 답변은 정확한 승인 인용이 속한 온전한 문장으로 구성합니다. 조건·예외나 문맥 의존이 감지되면 전체 문구를 유지합니다. ‘조건·예외 포함한 승인 원문’을 열어 전체 맥락을 확인할 수 있습니다. 사진 해석과 대상 연결의 의미 정확성은 AI가 틀릴 수 있습니다.

‘안내서 전체의 승인 설명에서 찾기’를 펼쳐 짧은 단어로 검색합니다. 여러 단어는 모두 포함된 단계를 찾습니다. 사진·비공개 메모의 의미 검색은 아니며 모델을 호출하지 않습니다.

작성 화면의 숫자 좌표는 ‘위치 세부 설정’ 안에 있습니다. ‘검토할 보완 질문’은 대화의 24시간 보관과 별도로 유지합니다. 단계 설명을 보완하고 새 승인본 반영을 확인한 뒤 ‘검토 완료로 표시’하고, 실수한 직후에는 ‘방금 완료 표시 되돌리기’를 누릅니다. 미처리 질문은 정상 질문 수나 대화 만료 때문에 사라지지 않습니다. 이 목록은 실제 사용자 효과 통계가 아닙니다.

처음 설치한 환경에서는 `python3 scripts/seed_demo.py`로 영어·한국어 보관표 데모를 각각 준비합니다. `/demo`는 영어 데모를, `/demo?lang=ko`는 한국어 데모를 엽니다. 각 언어는 마지막으로 준비한 시나리오의 승인 링크를 사용합니다. 별도 저장소는 `--data-dir /tmp/showme-demo`를 지정하고 같은 경로를 `SHOWME_DATA_DIR`로 서버에 전달합니다. 이 명령은 키 없이 사진·검토 문구·승인본을 생성하며 재실행 시 중복 생성하지 않습니다. 이후 `/demo` 또는 로그인 화면의 데모 링크로 열 수 있습니다. 생성·선택·질문을 실제 실행하려면 Meta API 설정이 필요합니다. [최신 수정 결과](REAUDIT_FIXES_RESULTS.md).


## 질문 응답 오류 진단

질문 모델에는 상태·목적별 제약을 가진 엄격한 스키마를 보냅니다. 제공자 내부 응답의 `result` 래퍼는 서버가 벗기므로 공개 질문 API 형태는 유지됩니다. `recheck_of` 응답 필드는 최초 보완 질문과 연결된 재확인 id 또는 null입니다.

모델 응답 실패의 진단 정보는 표준 오류 로그와 로컬 SQLite `model_failures`에 남습니다. 최근 30일·최대 200건을 보존하며 API 키·사진·질문·모델 응답 원문을 저장하지 않습니다. JSON/구조/상태 모순/인용/HTTP 단계를 구별합니다. 기록은 공개 API에 노출하지 않습니다. 과거 보존되지 않은 오류의 원인은 사후 복구할 수 없습니다.

검사 의존성은 `requirements-dev.txt`로 설치합니다. 새 스키마의 계약 검사는 jsonschema를 사용합니다. [최신 결과와 한계](NOVEL_REAUDIT_RESULTS.md).


## R10·R11 평가와 응답 지연

`python3 scripts/evaluate_semantics.py --split sealed`는 사전 고정 세트 해시와 계획만 검사합니다. 실제 호출은 `--execute`로 실행합니다. `--mode baseline --split discovery`는 기존 단일 호출 경로와 비교합니다. 제품은 새 의미 판단 서비스를 쓰므로 과거 evaluate_answers.py 결과를 현재 제품 정확도로 사용하지 않습니다.

R12 2차 이후 새 단순 외형 질문은 한 차례로 답하고, 업무·조건·선택 대상·확인 대화·미해결 답변은 별도 전체 교정 검토를 유지합니다. 최초 해석·재검토의 추론 깊이를 명시적으로 낮추고 교정을 두 번째 응답에 포함해 최대 두 차례입니다. 명시적 사진 전용 빠른 질문은 기존 한 차례를 유지합니다. 검토 오류 시 초안을 반환하지 않으며 서버 속도 제한도 유지합니다. 과거 R10·R11 평가의 중앙값은 약 23초였고, 현재 비교 수치는 [R12 검증](R12_RESULTS.md)을 참고하세요. 세트, 원본 응답, 판정 기준과 한계는 [평가 안내](../evaluations/r10-r11-v1/README.md)를 참고하세요.

R12 1차의 전체 검토/작은 검토 비교를 재현하려면 `python3 scripts/benchmark_latency.py`로 호출 없는 계획을 확인한 뒤 `--execute`를 붙입니다. 최대 140회이며 자동 재시도·응답 캐시·초안 공유가 없습니다. 이는 알려진 회귀 세트이며 새로운 독립 평가가 아닙니다.

최신 긴 대기 비교는 `python3 scripts/benchmark_reasoning.py --phase paired`로 먼저 호출 없는 계획을 확인하고 `--execute`로 실행합니다. 고정 28개와 같은 선택 질문 새 요청 3회를 각각 기존/수정 설정으로 비교하며 최대 155회입니다. 자동 재시도·초안 공유는 없습니다. [검증 범위와 구간별 시간](R12_TAIL_RESULTS.md).
