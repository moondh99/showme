이 문서는 R12 1차의 역사적 실행 기록이다. 현재 제품의 추론 깊이·최대 2회 교정 방식과 후속 비교는 [긴 대기 개선](R12_TAIL_RESULTS.md)을 참고한다.

## 변경

최초 의미 해석·분류 프롬프트와 생성 스키마는 유지했다. 다음 조건을 모두 만족하는 새 단순 외형 답변만 두 번째 검토를 생략한다: 외형/정상 답변, 선택 대상과 이전 확인 대화 없음, 질문과 초안에 업무 표현 없음. 업무 표현 검사는 검토를 추가하는 보수적 경계이며, 목적을 키워드로 확정하지 않는다. 업무 명칭을 포함한 외형 질문은 외형으로 답하면서 검토를 유지한다.

나머지 요청은 원래 사진·승인본·질문·선택 대상·후보 판단으로 별도 검토를 한다. 전체 답변을 매번 다시 생성하는 대신 `accept/none` 또는 `repair/고정 이유`만 반환한다. 잘못된 대상·조건·범위·인용·허용을 발견하면 기존 전체 교정을 한 번 추가한다. 보통 1~2회, 교정 시 최대 3회다. 검토·교정 실패 시 초안을 반환하지 않고 기존 오류 안내로 종료한다. 명시적인 사진 전용 질문은 기존 한 번 호출을 유지한다.

인용 원문 검사, 조건의 답변 근거 포함, 미확인/근거 없는 allowed 제한과 대상·상태 일관성 검사는 그대로 적용한다. 공개 응답 계약과 승인본을 바꾸지 않았다. 내부 지표에 실제 호출 수·각 호출 지연/토큰·검토 방식과 사유를 기록한다. `full` 비교 경로는 내부 평가용이며 공개 요청으로 검토를 끌 수 없다.

## 실제 API 비교

R10·R11의 질문 28개·규칙·사진·기대값 해시를 변경하지 않았다. 이미 개발에 사용한 세트이므로 이번 실행은 고정 회귀 평가이며 새로운 독립 평가가 아니다. 각각 새 요청으로 종전 `full`과 새 `adaptive`를 실행했다. 사례 순서를 섞고 방식 선후를 14개씩 교대했으며 동시 최대 2개, 자동 재시도·응답 캐시·초안 공유는 없다. 공급자 내부 캐시 동작은 제어하지 않았다.

시간은 서버 답변 함수 전체의 실제 대기이며 브라우저 통신·렌더링·SAM 시간은 제외한다. P95는 최근접 순위다. 실패와 느려진 사례를 제외하지 않았다.

28개 전체 자동 기준은 두 방식 모두 통과했다. summary의 quote_coverage 28/28에는 인용이 필요 없는 질문이 포함되므로 위에서는 실제 인용 그룹이 있는 17개로 보고한다. 선택된 위치와 자연어 대상, AND/OR, 다른 필드의 조건, 나이/반납 미확인, 용도 다른 표의 권한 전용과 없는 규칙을 최종 서비스 응답에서 내부 검토했다.

- D09·V07·H04: 다른 필드의 확인·선행·미성년 조건 포함.
- D06·D11·V06·H06·H07: 다른 대상의 권한을 옮기지 않고 blocked.
- D12·V08·H08: 근거 없는 규칙은 insufficient_information.

평가 세트의 문자열·기대 판정은 자연어 의미 전체의 증명이 아니다. 금지 문장의 조건 상태는 모델이 적용 여부/충족 여부로 다르게 표현할 수 있어 형식 논리의 원자 명제 정확도로 계산하지 않는다. 최종 대상·판정·원문 조건의 적용을 중심으로 확인했다. 같은 모델 검토는 오해를 반복할 수 있고, 오분류된 외형 답변이 업무 표현 보호까지 빠져나갈 가능성을 이 작은 세트만으로 배제하지 못한다.

## 폐기한 시도

초기에는 검토 판정 안에 전체 교정 답변 스키마를 중첩했다. 실제 V03 검토가 시간 초과했고 총 96.660초로, 같은 canary의 종전 22.678초보다 나빴다. 적용하지 않았다. 이 실패 원인이 스키마 처리인지 공급자/통신 변동인지 구분할 증거는 없다. canary manifest·실패 응답·요약을 보존했다.

작은 판정 형식의 다음 canary는 두 방식 모두 통과했다. 최종 교차 필드 제약 스키마로 28개 전체 비교를 실행했으며, 최종 제품 소스 해시가 manifest와 일치함을 확인했다. canary 하나의 큰 단축률을 전체 효과로 사용하지 않았다.

## 자동 검사와 남은 범위

자동 검사 **108개(Python 103·JavaScript 5)**가 통과했다. 새 단순 외형 1회, 업무 표현/선택/확인 대화/미해결의 검토 유지, 모든 업무 판정의 검토 유지, 잘못된 후보의 교정, 검토/교정 오류 시 응답 유보, 최대 3회, 모든 성공 호출의 사용량 합산, 판정 스키마 일관성, 승인되지 않은 조건 차단과 unknown/not_met 허용 제한을 포함한다.

최종 고정 세트에서는 교정 필요가 발생하지 않아 모두 최초 해석+승인 검토 또는 단순 외형 1회였다. 세 번째 교정·실패 경로는 모의 응답으로 검사했고 이번 세트에서 실제 교정 지연을 관측한 것은 아니다.

R12의 호출 정책 구현과 내부 회귀·지연 비교는 완료했다. **긴 대기와 사용자의 대기 수용성은 미해결**로 체크리스트에 유지한다. 새 사진·외부 사람 검수·현장 효과·외부 배포·최종 제출 완료를 뜻하지 않는다.

## 실제 제품 API·브라우저

통과한 소스로 로컬 서버를 재시작하고 학습 화면을 새로 열었다. 같은 승인본에서 실제 브라우저 입력→질문 API→Meta→서버 저장→판정 화면을 확인했다. 모의 응답이 아니다.

| 화면 요청 | 실제 판정 | 호출 | 모델 호출 합계 대기 |
|---|---|---:|---:|
| 노란 쟁반 외형 | appearance/visual | 1 | 7.845초 |
| 외형 직후 교육 미이수·책임자 동행 | procedure/allowed, OR 전체 met | 2 | 18.714초 |
| 파란 보관표 SAM 선택 후 교육 이수를 이유로 장비 반출 | procedure/blocked, 파란 보관표 | 2 | 47.453초 |

직접 선택의 실제 SAM은 1회·3.183초, 지점 240/641, 앞쪽 파란 표의 윤곽을 반환했다. 화면 픽셀을 정규화하며 계획 지점 240/640에서 y가 1 차이 난 결과다. 선택이 질문과 같은 승인본·단계·사진에 연결됐고, 다른 표의 OR 허용을 보관표에 옮기지 않았다. 외형 답변 직후 업무 요청도 정상 처리됐다. 화면에 실제 가정과 담당자 확인 안내가 남아 있다.

세 값은 모델 호출 시간 합계이며 브라우저 통신·그리기 시간의 직접 계측은 아니다. **마지막 실제 질문이 47.453초였다는 점이 긴 대기 미해결의 추가 증거다.** 최초 해석 29.573초와 작은 검토 17.880초로, 호출 수 감소만으로 이 변동을 해결하지 못했다. 제품 요청에는 기존 방식과 짝지은 비교가 없으므로 브라우저가 일정 비율 빨라졌다고 주장하지 않는다.

실제 서버 저장의 목적·대상·조건·호출 방식까지 확인했다. 브라우저 경고·오류는 없었으며 승인본 7개의 원문 해시가 모두 보존됐다. 새 승인본·규칙·질문 정답을 추가해 고정 평가 결과를 바꾸지 않았다.

이번 작업의 실제 호출은 **Muse 120회·SAM 1회**다. 폐기 canary 4회(검토 시간 초과 포함), 작은 판정 canary 4회, 28쌍 비교 107회, 브라우저 5회다. 실패 호출의 사용량은 완전히 보고되지 않아 전체 토큰을 청구 집계로 사용하지 않는다. 청구 금액과 계정 잔액은 조회하지 않았다.
