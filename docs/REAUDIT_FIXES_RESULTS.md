## 실제 Meta 호출 — 이번 수정 후 추가 9회

호출 전에 `state/evidence/reaudit-fixes-plan.json`에 예상 결과를 고정했다. 기존 연출 사진을 재사용한 내부 회귀다. 재평가 당시의 9회·이전 개발의 7회와 이번 횟수를 섞지 않는다.

- SAM 2회: 390px 모바일의 파란 펜 직접 클릭, 데스크톱의 검은 펜 키보드 선택. 모두 실제 윤곽 확인.
- Muse Spark 6회는 실제 로컬 학습 API와 저장소를 통과했다: 빠른 사진 관찰, 그 직후 일반 규칙 질문, 파란 펜 용도, 검은 펜 용도, 브랜드/구매 시점 정보 부족, 과거 사진 모드의 규칙 질문.
- 추가 Muse Spark 1회는 조건 보존 검사다. 같은 연출 사진과 ‘파란 펜은 운영자 메모용으로만 사용합니다. 단, 잉크가 마르지 않으면 사용하지 않습니다.’라는 통제된 문맥을 실제 `answer_question` 함수에 전달했다. 조건을 포함한 전체 원문이 유지됐다. 이 통제 문맥은 실제 승인본에 저장하거나 사람 승인을 받은 업무 규칙으로 표현하지 않았다.
- 파란/검은 펜의 용도 응답은 서로 다르며, 규칙 응답의 모든 문장은 승인 문구에서 구성했다. 자동 목적 처리에 추가 분류 모델 호출이나 자동 API 재시도는 없다.

브라우저에서 실제 클릭·키보드·연속 질문, 완료 표시/복원, 전체 원문 열기 경로와 새로고침·재시작 뒤 자료를 확인했다. 정상 흐름의 경고·오류 로그는 없었다. 모바일은 Chrome 화면 크기 검사이며 실제 휴대전화 소프트 키보드 테스트는 아니다. 검사 후 화면 크기를 복원했다.

## 자동 검사

Python 64개 + JavaScript 5개 = **69개 통과**. 기존 58개에 사용자 흐름과 저장 경계를 다루는 11개를 추가했다. 첫 실행에서 모드·목록·대상별 답변·사진 근거 문제에 대한 실패를 확인한 뒤 수정했다.

```sh
python3 -m unittest discover -s tests -q
node --check web/app.js
node --check web/selection.js
node --check web/guide-search.js
node --test tests/selection_ui.mjs tests/guide_search.mjs
git diff --check
```

핵심 검사는 `tests/test_reaudit_fixes.py`다. 실제 모델 응답의 정확도와 별개로, 목적 상속·이전 화면 호환·다른 안내서/비로그인 접근 제한·오래된 대화 정리 뒤 보완 유지·기존 질문 이관·완료 복원·문장 중간 인용/반복 인용·뒤따르는 예외·긴 조건 문맥 재검증을 확인한다.

## 남아 있는 한계

- 질문 목적 판단은 한국어 표현을 사용하는 보수적인 규칙이다. 모든 표현·다국어를 정확하게 분류하는 의미 판정기가 아니다. 모호한 질문은 승인 규칙 경로를 우선한다. 사진 관찰의 정보 부족 응답은 사진만의 한계로 설명하고, 사용자가 원하면 승인 규칙에서 다시 확인할 수 있다.
- 발췌는 정확한 원문과 문장 경계를 사용하며, 조건·예외나 의존 표현을 감지하거나 인용이 중복되면 전체 문맥을 유지한다. 모든 조건의 의미적 연결을 자동으로 증명하지는 않는다. 전체 승인 원문을 답변에서 다시 열 수 있다.
- 선택한 대상에 잘못된 승인 문장을 연결하거나 사진 관찰 자체를 틀리는 모델 오류는 여전히 가능하다. 이번 결과를 일반 정확도·사용자 작업 시간 절약으로 표현하지 않는다.
- 실제 작업 자료·사람 비교·독립 사진 평가·외부 영속 배포·최종 영상과 제출은 I11~I15에 남긴다.
