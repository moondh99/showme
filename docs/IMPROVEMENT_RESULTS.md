# 비판 기반 개선 — 구현·검증 결과

이 문서는 첫 수정 시점의 기록이다. 재평가에서 확인한 모드 잔류·보완 질문 누락·전체 문단 응답·모바일 순서는 이후 [재평가 결함 수정 결과](REAUDIT_FIXES_RESULTS.md)를 따른다.

2026년 11월 2일 KST. [개선 체크리스트](IMPROVEMENT_CHECKLIST.md)를 먼저 저장한 뒤 I01~I10을 구현했다. I11~I15는 실제 자료·사람 평가·배포·제출이 필요한 후속 작업이다.

## 구현한 변경

| 항목 | 변경과 확인 근거 |
| --- | --- |
| I01 신뢰 표현 | ‘근거를 확인한 답변’을 제거했다. 업무 규칙은 ‘관련 승인 원문’, 사진 관찰은 ‘사진을 보고 답한 AI 응답’으로 구분한다. 대상과 원문의 연결에는 AI 해석 오류가 있을 수 있음을 응답 옆에 표시한다. |
| I02 반대 지시 | 승인 문구와 반대인 자유 답변을 넣은 재현 검사가 수정 전 실패했다. 수정 후 서버는 인용된 승인 필드의 전체 원문으로 답변을 재구성한다. 조건·예외를 자르지 않으며, 반대 지시의 자유 답변은 사용자 응답과 질문 저장 기록에 남지 않는다. |
| I03 질문 목적 | `procedure`와 `appearance`를 구분했다. 전자는 사진만 근거로 답하지 못하며, 후자는 선택 상태에서도 사진 외형·위치 질문을 허용한다. 사진 관찰 요청에는 업무 규칙·제목·강조 이름을 모델에 전달하지 않고 단계 ID와 사진만 전달한다. 목적은 확인 대화에 고정되어 재시작 후 다른 목적으로 같은 대화를 잇는 요청도 거절한다. 기존 요청의 기본값은 보수적인 `procedure`다. |
| I04 작업 화면 | 단계 탐색을 선택 상자로 압축하고 사진 위에 선택 버튼을 배치했다. 질문을 설명·완료 제어보다 먼저 보여주고, 승인 설명은 바로 읽을 수 있게 유지했다. 데스크톱 사진·질문을 나란히, 작은 화면에서는 사진 다음 질문으로 연결한다. |
| I05 빠른 질문 | 선택 뒤 용도·규칙 또는 색·모양·위치를 한 번 눌러 질문할 수 있다. 선택만으로 질문 API를 자동 호출하지 않는다. |
| I06 작성 부담 | 숫자 좌표와 제목·목표 편집을 접었다. 사진 조작과 단계 메모·설명 검토는 유지했다. 접은 좌표 편집을 다시 열 수 있고 저장 시 숨겨진 필드도 보존한다. |
| I07 다른 단계 찾기 | 이미 전달된 승인 제목·설명·완료 확인에서 키워드를 검색한다. 원문과 해당 단계 이동을 제공한다. 비공개 메모 제외, 모델 호출 없음. 자연어 의미 검색은 아니다. |
| I08 담당자 보완 | 해당 안내서에서 최근 정보 부족으로 답하지 못한 질문을 인증된 작성자에게 보여준다. 해당 단계 보완으로 이동한다. 자동 내용 수정·새 승인본 생성은 하지 않는다. 질문 보관은 24시간이다. |
| I09 체험·재현 | 명시적으로 지정된 데모만 로그인 전에 노출하고 `/demo`에서 연다. `scripts/seed_demo.py`가 공개 연출 사진·검토 문구로 빈 저장소에 데모를 만들며 중복 실행해도 승인본을 늘리지 않는다. |
| I10 이력·회귀 | 로컬 Git 저장소와 수정 전 기준 이력을 만들었다. DB 백업·승인본 해시를 보관하고 신뢰 오류, 질문 목적 고정, 작성자 권한, 원문 검색, 데모 재현 검사를 추가했다. |

## 실제 화면·API 확인

내부 검증이며 사진은 기존 AI 연출 행사 접수대 사진이다. 현장 사용자 관찰이나 미사용 사진 평가를 대체하지 않는다.

- 추가 호출 총 7회: SAM 2, Muse Spark 5.
- 데스크톱에서 키보드로 파란 펜을 선택한 지점 `(820,550)`에 실제 SAM 마스크를 받았다.
- 빠른 규칙 질문은 파란 펜의 운영자 메모용 규칙을 인용했다. 개발 중간에는 인용 문장을 반환했고, 최종 정책은 인용된 필드 전체를 반환하도록 강화했다.
- 사진 관찰 질문은 파란색·가늘고 긴 펜·클립보드/검은 펜의 오른쪽이라는 외형과 위치를 답했다.
- 브랜드·구매 시점 질문은 정보 부족으로 유보했다. 담당자 화면의 보완 질문 목록에서 새 질문을 확인했다.
- 사진 관찰에 업무 규칙을 전달하지 않는 최종 경계도 실제 API로 한 번 더 확인했다. 파란색 펜과 사진 오른쪽 위치를 사진 근거만으로 답했다.
- 최종 정책 반영 후 서버를 재시작했다. Chrome 390×844 화면에서 사진을 직접 클릭한 지점 `(819,548)`에 SAM 윤곽을 받고, 빠른 질문으로 현재 단계의 전체 승인 설명을 받았다.
- 390px 화면의 문서 폭은 375px(스크롤바 제외)로 가로 넘침이 없었다. 실제 휴대전화와 소프트 키보드 검증은 아니다.
- 1280×720 데스크톱의 초기 스크롤 0 기준 선택 버튼 약 372px, 질문 제목 421px, 입력창 634px. 이전 평가의 선택 버튼 749px·질문 제목 935px에서 앞당겨졌다. 작업 시간 감소 측정은 아니다.
- ‘명찰’ 검색으로 3·4단계의 승인 설명을 찾고 3단계로 이동했다. 단계 이동 중 기존 단계의 선택·질문 상태는 분리된다.
- 로그인 전 데모 링크, 작성 화면의 좌표 접기·펼치기, 정보 부족 질문 새로 확인을 브라우저에서 실행했다. 정상 흐름의 브라우저 경고·오류 로그는 없었다.
- 내장 브라우저에서는 크기 재정의가 실제 적용되지 않아 모바일 검사에 사용하지 않았다. Chrome에서 실제 `innerWidth=390`을 확인한 뒤 검사하고 원래 크기로 복원했다.

## 자동 검사와 재현

Python 53개, JavaScript 5개, 총 58개 통과. 기존 48개에 신뢰·권한·질문 목적·재현·검색을 다루는 10개를 추가했다. 자동 검사는 모델 대체 응답과 저장소 경계를 확인하며 실제 공급자 성공률을 측정하지 않는다.

```sh
python3 -m unittest discover -s tests -q
node --check web/app.js
node --check web/selection.js
node --check web/guide-search.js
node --test tests/selection_ui.mjs tests/guide_search.mjs
git diff --check
```

외부 키 없이 새 데모 데이터 만들기:

```sh
python3 scripts/seed_demo.py --data-dir /tmp/showme-demo
SHOWME_DATA_DIR=/tmp/showme-demo python3 scripts/serve.py
```

설명·사진 조회와 검색은 키가 필요 없다. 실제 SAM 선택·AI 질문·초안 생성에는 Meta 키와 사용 가능한 크레딧이 필요하다. seed 명령은 모델을 호출하지 않는다. 임시 빈 저장소에서 명령 실행과 4단계 공개 조회·사진 조회·중복 생성 방지를 확인했다. 샘플 작성자 비밀번호는 해당 데이터 폴더에서 생성된다.

기존 승인본 3개의 저장 내용 SHA-256이 변경 전후 동일했다. 보관 자료:

- `state/evidence/critique-improvement-api.json`: 실제 요청 결과·목적·시간·사용량과 검사 범위

## 남은 한계와 다음 판단

업무 규칙을 자유롭게 바꾸어 말하는 경로는 줄였지만, 관련 없는 승인 문구를 선택한 물체에 잘못 연결하는 문제는 완전히 막지 못한다. 사진 관찰도 AI 출력이며 의미 정확성을 서버가 증명하지 않는다. 원문 전체를 반환하므로 답변이 길어질 수 있다. 추가 의미 검증 모델을 붙여 지연을 늘리는 대신 채택한 절충이다.

현재 대표 시나리오는 계속 연출된 접수대다. 새로운 현장 작업과 정적 안내서 대비 사람 관찰이 있어야 문제의 중요성과 시간 절약을 판단할 수 있다. 개발에 쓴 사진으로 수행한 기존 48회 평가와 이번 7회 호출을 독립 정확도나 사용자 효과로 합산하지 않는다. 답변 정책·프롬프트가 변경되었으므로 v1 평가 수치를 현재 버전의 정확도로 재사용하지 않는다.

첫 화면의 핵심 기능 발견과 반복 입력은 개선했지만 사용자 작업 시간·작성 시간 감소는 아직 측정하지 않았다. 외부 영속 배포, 최종 영상과 실제 제출은 남아 있다.
